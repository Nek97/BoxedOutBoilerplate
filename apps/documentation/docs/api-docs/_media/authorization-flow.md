# Authorization flow

![img](https://docs.google.com/drawings/d/e/2PACX-1vRVaRe-WLx-vx_EN9CL_E7HAhBIHwpG-9VRY8dbUadwVkn0b1xpuEmUBXGWlm81eronbKZOhBcgWxba/pub?w=956&h=587)

Our authorization is composed by 2 different kind of JWT token:

- **Public JWT:** this JWT is generated by our **login** mutation and authorized by the gateway service. It's only used for the communication between the end-user client and the gateway itself.
  This JWT should contain limited information strictly necessary for the client. The public JWT must be verified by checking the information contained in our DB (such as the ActiveSession and the Roles).

- **Private JWT**: this JWT is generated by the gateway right after the **Public JWT** is authorized and it's only used internally to communicate with the services connected to the gateway.
  This JWT doesn't need any verification with the database, we trust that the secret to generate it resides in the Gateway only and that the connected services are not exposed to any public network.
  The payload of the Private JWT could contain all the information needed to avoid a further query to the database to retrieve information  which has already been fetched by the gateway.
